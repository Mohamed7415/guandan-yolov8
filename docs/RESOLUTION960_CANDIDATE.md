# 960 分辨率候选模型（2026-10-19）

新候选显著减少了已知数据上的误报与漏检，尚未达到大规模新盲测验收。正式 v1.0.0 模型及发布附件保持不变。候选 ONNX 单独发布于 [v1.1.0-rc1 预发布](https://github.com/Mohamed7415/guandan-yolov8/releases/tag/v1.1.0-rc1)。

## 实验与选择

以正式 v1 权重初始化新的 YOLOv8n 训练，保留原 1392/400/208 张划分。训练使用 `prepared_full2000_review_v2`，输入 960、batch 2、seed 42、上限 40 轮；实际完成 38 轮，第 13 轮为最佳，之后连续 25 轮未改善而提前停止。没有使用新采集的 48 张开发图训练本候选。

导出 FP32、opset 12，输入 `[1,3,960,960]`，输出 `[1,58,18900]`。五张真实验证图的 PyTorch/ONNX 原始输出数值一致性检查通过。最终识别仍只有一个 ONNX、置信度过滤及标准 NMS，不依赖模板或第二模型纠错。

预先固定置信度 0.25、NMS IoU 0.45、匹配 IoU 0.5，在相同的 400 张验证图上比较两种模型和两种标准 NMS。选择规则要求每张图、每个类别的漏检不增加，并减少总误报、提高整图全对数量。只据验证集选择后，冻结候选配置，再评估旧回归和新开发图。

| 模型与 NMS | TP | 误报 | 漏检 | 整图全对 |
|---|---:|---:|---:|---:|
| v1 640，类别感知 | 7791 | 121 | 10 | 294/400 |
| v1 640，跨类别 | 7788 | 15 | 13 | 386/400 |
| 960，类别感知（选中） | 7800 | 5 | 1 | 394/400 |
| 960，跨类别 | 7798 | 4 | 3 | 395/400 |

跨类别 NMS 会压掉部分真实牌，因此没有选用。命令行中的 `--agnostic-nms` 仅供明确的实验复现，默认仍为类别感知。不得把少输出造成的误报下降当作全对。上述分数保留选模时冻结的 v2 标签；[完整比较及场景分项](../reports/published/resolution960_v1_validation_comparison.json)也记录了逐图漏检变差的情况。

## 冻结后的回归

| 数据 | v1 640：误报/漏检/全对图 | 960：误报/漏检/全对图 |
|---|---|---|
| 208 张旧回归，v2 标签 | 22 / 1 / 190 | 2 / 0 / 206 |
| 48 张新开发图，890 张牌 | 5 / 3 / 41 | 0 / 0 / 48 |

旧回归剩余两处错误都在 2♥ 条带额外输出 8♥，不是漏标。新开发图来自两个已观察的实际对局，整批保守地保持同一拆分单元。它们已用于诊断，48/48 不能推导未来画面全对。审核者为助手，尚无独立人工二审。新的独立盲测计数仍为 **0**，10000 张、100 个独立对局的目标尚未完成。

详见 [208 张回归结果](../reports/published/resolution960_v1_regression208.json)、[48 张开发回归及场景分项](../reports/published/resolution960_v1_development48.json)。场景标签可重叠，不能将各场景图片数相加当总数。

后续原图复核又确认验证图 `01411`、`01413` 各漏标一张清晰可辨的 Q♥。修正计划单独保存于 [追加补丁](../configs/annotation_revisions/20261019_visible_qhearts_val.json)，另建 v3 标签版本；不改写上面的选模结果、训练记录或 v2 数据。修订后的成绩另行记录，不能将标注修订声称为模型进步。

相同候选在新 v3 标签上重新评测为 **TP7802 / FP3 / FN1，396/400 张全对**，见[追加复核成绩](../reports/published/resolution960_v1_retrospective_v3_val.json)。仍存在两处小王位置额外输出大王、一处 9♠ 位置额外输出 9♣，以及一张带金色花色标记的 5♥ 漏检；这些真实问题保留，不按模型输出改标签。

全批开发复核完成后，相同候选在 98 张、1966 张牌上为 **TP1965 / FP1 / FN1，97/98 张全对**。新增发现半透明“二游”横幅下的小王错为大王；该图未包含在之前的 48 张抽样中。详见[全批复核](DEVELOPMENT_DATA_REVIEW.md)。这批图将用于下一轮训练，不能再算独立测试。预发布 ZIP 仅包含 ONNX 交付及配置，PyTorch 训练/恢复检查点仍保存在本地。

## 使用候选

将预发布 ZIP 解压到 `artifacts/candidates/`，使用仓库当前版本的推理脚本：

```sh
.venv/bin/python scripts/infer_onnx.py /绝对路径/游戏截图.png \
  --model artifacts/candidates/resolution960_v1.onnx \
  --confidence 0.25 --iou 0.45 --output reports/candidate_predictions
```

固定配置及模型哈希见 [候选配置](../configs/inference_candidates/resolution960_v1.json)。960 在本机四线程 CPU 的验证集平均 ONNX 执行时间约 75.6 ms，v1 约 31.5 ms；不含图像加载、预处理和 NMS，也不保证其它设备的速度。
