# 持续目标与恢复

用户于 2026-10-19 授权持续推进本项目，遇到账户周期限额、断网或电脑重启后接续。这项授权取代此前“仅检查并提建议”的范围限制。

## 验收目标

- 最终推理为单个 YOLOv8 ONNX 加固定标准后处理；不依赖模板或第二模型纠错。
- 在约定小程序主题、分辨率及可辨认牌面范围，争取零误报、零漏检、逐图全对。
- 本轮先以至少 10000 张真实新盲测图、至少 100 个真实独立对局/会话为可执行的验收下限；这是计划值，不能写成已完成。
- 原图来自原生小程序，不用网络视频、复制或生成图凑数量。按整局/会话隔离，真实组号必须可追溯。
- 标签审核冻结、模型和阈值冻结后再做盲测；分析过的测试批次变为回归集，最终验收另用新批次。
- 同时报逐图全对率、误报/漏检/错类、场景分项和对局数。mAP 是辅助；不能提高阈值、少输出或删除困难图片以制造全对。
- 旧 v1.0.0 模型、数据及指标保持可追溯。后续工作使用新数据版本与新候选路径。

## 每次接续

1. 读取本文件和 `reports/continuous_goal/state.json`、`journal.jsonl`、必要时 `state.previous.json`。
2. 检查现有进程、输出文件、冻结指纹和检查点，先确认前次工作是否实际完成。不得重跑已有任务或并行修改同一数据版本。
3. 以错误证据选择下一步：原图标注复核 → 修复数据与恢复流程 → 真实采集/审核 → 冻结分组数据 → 训练实验 → 导出与回归 → 新盲测。
4. 每个阶段将证据路径、数据/模型哈希、任务参数、最近有效检查点、下一步写入状态。可用 `scripts/goal_recovery.py update --changes '{...}' --event '...'` 原子保存；不要把“开始运行”记成“已完成”。
5. 长任务参数和数据指纹在启动前写入。`train.py --resume <run>/weights/resume.pt` 恢复模型、优化器及轮次，核对原数据/分组指纹；最新文件损坏会检查 `resume.previous.pt`。`--weights` 只表示从权重重新初始化。断点恢复已通过真实 YOLO 小规模强制退出/恢复验证，并在恢复后第一次更新之前比较优化器张量与参数组；真实物理断电未验证。证据在 `reports/continuous_goal/recovery_smoke_20261019_r4/result.json`。
6. 只有全部验收条件确实达成才将 Goal 标记完成，并关闭本聊天的恢复调度。用户叫停时立即停止其相关任务和调度。

## 调度及限制

- 当前聊天的应用内自动任务：`automation`，每 30 分钟尝试接续；使用原聊天上下文，不创建独立任务。
- macOS 用户 LaunchAgent：`com.guandan.yolov8.goal-recovery`。登录用户的桌面会话后启动，每 5 分钟确认宿主应用在运行；不模拟鼠标、不启动游戏、不调用模型、不购买额度。训练与采集由本聊天目标后续阶段管理，这个服务本身不承诺恢复训练。
- 有效启停状态在 `reports/continuous_goal/state.json` 的 `enabled`；`enabled=false`、`stage=stopped/completed` 或缺失/损坏状态时恢复服务不启动应用。恢复健康记录与阶段进度分别保存，防止互相覆盖。
- 配额不足时尊重平台停止，不消耗重置权益、不买额度、不切账号、不绕过限额。每次可用的后续调度再尝试继续；不承诺精确在额度刷新瞬间唤醒，平台对限额状态的实际处理以应用为准。
- 断网时本地任务可完成已授权的离线步骤；在线智能调度要等联网恢复。关机和睡眠期间不执行工作。重启后必须先登录/解锁 Mac，应用才能恢复。
- 用户于 2026-10-19 明确要求开启防休眠。当前任务恢复服务以 `caffeinate -d -i -s -w <恢复服务PID>` 防止屏幕和系统因空闲休眠，适用于外接电源和电池；状态中 `recovery.keep_display_and_system_awake=true` 表示该选择。默认未选择时只使用外接电源防睡眠的 `-s`。断言跟随恢复服务进程，服务停止或目标关闭时释放。此设置不修改 FileVault、自动登录、系统密码、自动锁定规则或全局休眠设置，也不能解锁已经锁定的屏幕、保证合盖后继续运行。
- 微信掉线、系统解锁或系统要求人工重新验证时，保存进度并提出一次明确操作请求，不能保证无人完成身份验证。
- 仅继续此前授权的普通虚拟金蛋游戏和截图，不付费/充值。

## 停止恢复

对本聊天说“停止持续任务”，让助手同时停止目标、应用内自动任务和此服务。也可手动卸载：

```sh
.venv/bin/python scripts/goal_recovery.py update --changes '{"enabled":false,"stage":"stopped"}' --event user_stopped
launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/com.guandan.yolov8.goal-recovery.plist
```

卸载服务不会删除数据和训练检查点。当前恢复配置仍需在真实断电/登录后观察验证，不能把静态检查说成实际断电验证。
