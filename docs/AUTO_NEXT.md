# 普通场自动续局与截图

双击项目根目录的 `开始自动续局采集.command`。运行前应已在**普通金蛋场**开始一局，并开启游戏自己的托管。脚本只接续普通结算页，不负责从大厅选择场次，也不负责出牌。游戏是否跨局保留托管由游戏本身决定。

默认最多续局 10 次、运行 60 分钟；截图器本批保存到 200 张候选时，续局器也会结束。运行时保持《天天爱掼蛋》窗口在前台、未最小化。切换其他应用时不会点击。按 Ctrl+C，或把鼠标移到屏幕左上角停止。窗口关闭、未知界面持续 60 秒、续局后 45 秒未见新对局，均停止。

不会点击充值、购买、赛事或匹配大厅。除结算续局外，现有模板还覆盖已观察到的连接重试、升级确认、关闭付费优惠弹窗，以及普通虚拟金蛋补给/广告奖励流程；每种情况要求多处图像锚点同时匹配，见 `configs/ui_templates/extra_actions.json` 和 `scripts/auto_next.py`。这不是只点击“再来一局”的通用按钮脚本。未知弹窗会停止。仅用于普通虚拟游戏币场，不要在带现金、实物或礼品卡奖励的赛事中运行。

## macOS 权限

依赖已安装在本项目 `.venv`。若换机器，可运行 `.venv/bin/python -m pip install -r requirements-capture.txt`。

双击启动时，macOS 可能要求为终端启用“屏幕与系统音频录制”和“辅助功能”。需要用户在系统设置中手动授权，并按系统要求重开终端。脚本不改系统权限。仅截图不需要辅助功能权限。

## 识别范围与验证

脚本从本小程序真实结算图建立三个独立模板：下一局文字、总倍数标题、查看牌局/回放/分享工具。三处均需位置、形状及颜色匹配，并连续观察两次。点击前重新截图、核对窗口位置和前台进程。弹窗导致的整体变暗会被颜色误差检查阻止。

模板适配目前观察到的 1620×1000 窗口比例，可适应等比例 Retina 放大。改变窗口比例、游戏改版或换布局时会拒绝匹配，须重新检查模板。一次点击后，必须连续三次看到绿色牌桌及牌面才解锁下一次点击；点击尝试不等于成功开局。

已经通过离线检查：真实结算匹配、等比例放大、遮罩弹窗拒绝、单个黄色按钮拒绝、重复点击抑制、新局确认、超时停止，以及已观察弹窗的多锚点匹配。2026-10-17 已在本机普通初级场实际观察自动续局进入新对局；此后用于完成真实截图采集。历史运行日志保留在本机，未作为仓库运行依赖。升级、补给、广告等流程仅覆盖已观察模板，换界面不能保证自动完成。

只识别、不发送点击的检查命令：

```sh
.venv/bin/python scripts/auto_next.py --once
.venv/bin/python scripts/auto_next.py --dry-run --max-minutes 1
```

真实点击前截图及动作记录保存在 `reports/auto_next`；普通观察截图不会写入动作记录。

## 截图与后续训练

候选原生 PNG 保存在 `data/candidates/auto_日期_时间_编号/`。采集器只截严格匹配名称、所属微信进程的小程序窗口，不回退到桌面全屏；保留原始 PNG 字节。比较牌面区域，过滤静止重复、较大动画、黑屏及部分无明显牌面的界面。这个过滤器不是识牌模型，仍可能保留重复或无效画面。

每批生成 `captures.csv`（时间、原图 hash、窗口编号和序列）及 `review.csv`（默认待审核）。候选数量不计入正式 200 张目标；截图本身不包含自动生成的牌标签。一个采集序列默认归为同组，避免误把自动重启或相邻帧拆进训练和测试。复核真实对局边界后可补 `session_id`；同一局在不同批次必须填同一局号。

在 `review.csv` 中为合格截图填写场景（`self_play|others_play|pass|fan|sorted|negative` 中实际出现的场景），确认组别，将 `approved` 设为 `true`。先预览、再导入：

```sh
.venv/bin/python scripts/import_capture_run.py data/candidates/实际批次目录
.venv/bin/python scripts/import_capture_run.py data/candidates/实际批次目录 --apply
.venv/bin/python scripts/audit_capture.py --target 200
```

导入逐字节复制到 `data/raw`，保留候选原图和已有标注审核状态，新条目一律 `reviewed=false`。然后使用原有 X-AnyLabeling 入口标注、复核，再运行训练流程。脚本不会用无标注图自动训练。

## 前台恢复选项（待真实续局验证）

普通脚本在游戏不处于前台时继续拒绝点击。新增 `--activate-before-click` 可在确认已知结算或已知提示后，将游戏窗口置前；它可能切换当前正在使用的前台应用。先前仅在启动时置前一次，无法应对后续焦点被其他应用取走。

该选项先核对当前截图中的已知界面、窗口 ID、所属进程及位置，再置前同一游戏窗口；置前之后重新截图并再次核对。发送鼠标事件前还要确认前台进程及点击位置无遮挡。未知画面、冷却期、窗口变化、置前失败或临点击时焦点再次丢失，都不能发送点击。冷却期也不触发窗口置前。它不修改系统权限，不绕过前台守卫，不能与后台 `--targeted-input` 同用。

```sh
.venv/bin/python scripts/auto_next.py --activate-before-click \
  --capture-run-dir data/candidates/新批次目录 \
  --max-rounds 3 --max-minutes 12 --output reports/auto_next_新批次
```

六项新增离线检查覆盖默认不置前、未知界面、冷却期、置前后重新取图、焦点最后一刻丢失及窗口身份变化；全套 70 项本地检查通过。当前真实结算的三个识别锚点均匹配，但新选项尚未证明真实点击与下一局转场成功。待当前训练结束、确认无其他采集/输入任务后再做一次有记录的真实续局验证，不能把单元检查说成无人续局已经修好。

## 准备界面残留手牌（2026-10-20）

真实批次013的200、240、386帧在“准备中”时仍保留旧手牌，不能仅凭白色手牌区域确认新发牌。新增三个原生准备文字布局，各需三处文字锚点全部匹配；只保存不透明橙色文字轮廓，排除牌面、头像、倒计时及背景像素。逐通道空间相关度和颜色误差仍分别要求0.93及20，纯色块、变暗或任一锚点缺失均拒绝。

此判断只用于原生UI等待，不识别牌类别、不用于最终牌面后处理。原45/120秒固定期限、三次连续真实手牌确认、窗口/前台/遮挡/重截图守卫不变。101项离线检查通过，三张真实准备页均被拦截，后续真实发牌仍可确认；修复后在线遇到该准备变体并完成等待恢复尚待观察。控制器日志仍须结合原图审核，不能直接充当整局或独立会话计数。
