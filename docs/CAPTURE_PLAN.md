# 真实截图采集计划

先完成 200 张试采、标注和一次训练/验证，再扩大到 2000 张。所有数量都指**真实、非空、完整可解码、像素内容去重、元数据齐全的截图**。保留截图工具原始 JPEG/PNG 字节，不重编码。同时记录文件 SHA-256；即使无损重存导致文件 hash 改变，像素相同仍只能计一次。登录页、占位图、合成图、重复文件不能充当游戏截图。不得用复制、变换或生成图片凑足采集目标。

## 采集与场景

通过用户授权的电脑界面实际操作《天天爱掼蛋》，由 CUA 保存原始 JPEG/PNG，或使用用户另行要求的 macOS 窗口截图脚本采集原生 PNG。自动脚本候选先存 `data/candidates`，审核后再导入 `data/raw/`；使用方式见 [自动续局与截图](AUTO_NEXT.md)。后缀须与文件头一致：JPEG 使用 `.jpg` 或 `.jpeg`，PNG 使用 `.png`；把 JPEG 字节误存为 `.png` 时，只修正文件名，不能重编码。不得使用网络视频替代当前小程序实拍来源。

200 张试采建议覆盖至少 10 局；同一局尽量包含自己出牌、别人出牌、不要、手牌展开、整理完成和其他实际出现的界面。采集间隔应随牌面变化决定，静止画面不要连续凑数。可用下面的优先场景配额指导采集；一图可多场景，因此实际场景统计相加可超过截图总数。

| 优先场景 | scene | 试采建议 | 2000 张阶段建议 |
| --- | --- | ---: | ---: |
| 自己出牌 | self_play | 45 | 450 |
| 其他玩家出牌 | others_play | 45 | 450 |
| 不要/过牌界面 | pass | 25 | 250 |
| 牌面展开 | fan | 30 | 300 |
| 牌面整理好 | sorted | 35 | 350 |
| 实际无目标牌面的游戏界面 | negative | 20 | 200 |

`negative` 只表示原图确实没有需要标注的目标；含有可见目标牌面的“不要”界面应照常标注，不能标成空标签。登录过期时停止采集，等待用户完成登录。

## 文件与登记

默认将原图平铺在 `data/raw/`，推荐唯一文件名 `session001_frame0001.jpg`（实际为 PNG 则用 `.png`），便于在 X-AnyLabeling 中一次打开目录并统一设置输出位置。工具也接受子目录；使用子目录时需在标注工具中逐目录打开，并把标注输出到对应的 `annotations/` 子目录。`session_id` 是同一局的稳定 ID；同一局所有截图必须保持一致。`group_id` 表示临近帧组，建议 `session001-g001`。场景可以用 `|` 连接，例如 `self_play|sorted`。保存原始分辨率和原始字节，不裁切、重编码或覆盖原图。

```sh
.venv/bin/python scripts/register_capture.py data/raw/session001_frame0001.jpg \
  --session-id session001 --group-id session001-g001 --scene 'self_play|sorted' \
  --captured-at '2026-10-16T14:30:00+08:00'
```

以上命令只是用法示例，不会创建所示截图。传入现有 JPEG/PNG。外部图像可加 `--copy-to-raw`，逐字节保留原文件并拒绝覆盖。省略 `--captured-at` 时会使用文件修改时间并明确报告 `file_mtime_inferred`；有真实截图时间时应优先提供。重复登记同一路径可更新元数据；不同文件的完全重复图像会被拒绝。工具验证文件头、后缀和解码结果匹配，不会为了通过验证转换格式。

登记文件 `data/capture_manifest.csv` 固定字段为：

```text
filename,session_id,group_id,scene,captured_at,sha256,width,height
```

`filename` 相对于 `data/raw/`；`captured_at` 含时区；hash 和尺寸由真实文件读取。不要手填不存在的图片记录。

## 审计与划分

```sh
.venv/bin/python scripts/audit_capture.py --target 200 --require-target
# 扩充阶段将 --target 改为 2000
```

每次运行审计命令都会自动更新 `reports/capture_audit.json`：真实文件数、有效唯一数、有效已登记唯一数、剩余数、逐局/逐场景数量、损坏/空白、完全重复、近重复及元数据问题。登记命令只更新采集清单；每批登记后应再运行审计以刷新报告。达到目标以 `registered_unique_valid_images` 为准；空文件、透明/单色空图、损坏图像、后缀与格式不匹配、完全重复和未登记/错误登记图片均不计数。近重复使用 dHash 提醒人工检查，不能自动认定为重复；相同牌桌背景可能相似。报告最多列出 1000 对近重复，同时保留总对数。

图像中“未达到目标”和“数据无效”是不同问题。无真实截图时审计应明确显示 0，不能以示例素材代替。审计仅核实文件和登记信息，截图是否来自真实游戏及牌面/负样本是否合适仍需人工确认。

标注工具读取采集清单后，生成 `data/manifest.csv` 待审核清单，保留 `session_id`、`group_id` 和场景；图片须完成 X-AnyLabeling 标注并人工审核后才进入训练。

训练、验证、测试必须按 **整局 session_id** 划分，例如 70%/15%/15%，同局、临近帧和近重复跨局样本不可泄漏。200 张阶段每组都应包含实际对局；2000 张应扩充到更多对局、局面、分辨率/缩放和牌面组合，不能仅增加同一局的相邻帧。划分后检查场景与类别覆盖，再确定训练基线。
