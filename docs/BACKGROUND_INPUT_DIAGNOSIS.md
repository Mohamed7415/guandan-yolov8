# 后台输入排查（2026-10-20）

## 已证实的结论

“非前台应用”和“窗口不在当前桌面”需要分别检查。微信不是前台应用时，Computer Use 仍能点击这款小程序，本轮已实际关闭推广、确认免费5000虚拟金蛋奖励；操作前后前台应用均为Codex，未调用置前动作。

此前 `noWindowsAvailable` 不足以说明“必须前台”。失败时，AX仍能读到游戏窗口，原生按固定窗口ID截图也成功，但该窗口没有出现在当前屏幕可见窗口列表。当前窗口进入可见列表、重新绑定后，CUA截图和坐标点击均成功。故障已缩小至窗口定位/跨桌面的可操作性差异；尚未通过同一会话主动切换桌面的对照实验排除全部其他因素，不能把相关性写成已完全证明的唯一根因。排查没有切换用户桌面、激活微信、修改权限或打断电影。

## 两条输入链路不能混为一谈

| 路径 | 实测结果 | 能说明什么 |
| --- | --- | --- |
| 原生窗口截图脚本，默认当前屏幕枚举 | 窗口离开当前桌面时找不到 | 本项目的枚举范围限制；已在c412799增加显式固定ID后台读取 |
| 原生脚本 `CGEventPostToPid` 定向输入 | 先前发送一次续局事件后45秒未见新发牌，安全停止 | 未核实有效输入；API返回/日志“已发送”不代表游戏收到 |
| Computer Use，先前窗口不在当前可见列表 | AX/截图成功，点击报 `noWindowsAvailable` | 输入端没有取得可操作窗口，不是牌面检测错误 |
| Computer Use，当前可见但微信非前台 | 多次关闭不同提示、确认免费奖励，画面对应改变 | 已验证当前条件下真实后台点击；无需微信前台 |

微信主进程拥有实际小程序窗口；独立 `WeChatAppEx` 辅助应用本次没有AX窗口。选辅助应用会超时，不能因为是小程序就绑定这个无窗口辅助进程。主微信绑定此前也曾失败，因此辅助进程并非全部失败的唯一原因。

## 接续策略

- 后台截图继续使用固定原生窗口ID和所属进程校验，不回退全屏截图；保留原始PNG、去重、审核和断点记录。
- 用户使用其他应用时，手动UI恢复优先通过Computer Use；先绑定微信主应用、核对标题和新截图，再对已观察到的普通免费界面操作，并检查实际结果。
- 不把旧的CG进程定向事件当作Computer Use后台输入替代品，不反复发送先前无效的续局点击。
- 不自动置前、不主动切换桌面，不声称已解决全屏跨桌面、最小化、熄屏或锁屏状态下的全部输入问题。若同一错误再现，记录当时窗口可见性/所属进程及CUA结果，先处理其他离线工作。
- 本轮游戏还提示高级场虚拟金蛋不足。它属于游戏内状态，与`noWindowsAvailable`是不同问题；未购买、充值或点击付费领取。恢复普通采集前应检查余额并选择余额允许的普通场。

私人原生截图及前后台上下文在 `reports/continuous_goal/background_input_diagnosis/`，不公开。公开摘要只保留结论与验证范围，不含玩家截图。全部牌面候选仍待审核隔离；本次诊断不产生新的正式盲测或完整局验收计数。
